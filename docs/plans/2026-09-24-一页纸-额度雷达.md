# 一页纸 · 额度雷达（2026-09-24）

## 做什么
一个中文网页，转播 Codex 和 Claude 官方在 X 上发的「送额度／重置／提额」公告。搜「Codex 什么时候重置」的人进来一眼看到：上次什么时候送、送的是什么、给谁、原帖在哪。
纯引流站：只做流量入口，不接训练营、不接付费。

## 三问（我替你填的，你否决即可）
1. 谁在用：国内用 Codex / Claude Code 的付费用户。证据：两个英文同类站已存在且做了 SEO 布局；X 在国内看不了；官方公告只发在 X。谁付钱：暂无，纯引流。
2. 想看到的现象：有人从百度／谷歌搜「codex 重置」进来；来过的人发新模型时会回来看「这次送没送」。
3. 明确不做：个人倒计时；概率预测；模型质量评分；短信／电话付费提醒；托管用户账号或密钥；训练营导入（第一阶段）。

## 怎么算做完（你按这个试）
1. 手机打开网址，首屏看到两张卡：Codex 上次送额度是几号、送的什么；Claude 同样。
2. 往下翻时间线，任一条点「原帖」能跳到 X 原文。
3. 打开「常见问题」，能看懂「重置卡」和「直接重置」的区别。
4. 我在电脑跑一条命令，飞书收到「N 条新线索待确认」。
5. 我确认一条后重新发布，网站上多了这一条。

## 我替你定的决定
- 定了覆盖 Codex + Claude 两家，因为数据源同一条管线，你的用户两个都用。
- 定了事件分三类：全员重置（直接恢复）／重置卡（存账户随时用）／提额省额，因为这是两站混淆的根源。
- 定了每条事件必须带原帖链接、套餐范围、核验日期，没核实的不上首页。
- 定了「官方下次重置」永远写「尚未公布」，不放概率数字。
- 定了数据源：TikHub 拉两个官方账号的推文（约 $0.02/天）+ 两个同类站接口当免费线索 + fxtwitter 免费核原帖。
- 定了人工确认走命令行 + 飞书通知，因为第一阶段只有我在维护。
- 定了零依赖 Node 静态生成 + Vercel 静态部署，因为页面简单，越少东西越不坏。
- 定了中文优先、北京时间、手机优先，不做英文版。
- 定了页面上留一个「关注入口」空位（默认隐藏），你以后填公众号或微信即可，不动代码。
- 定了域名先用 Vercel 临时域名，正式域名等你拍板再绑。
- 视觉：先用干净默认皮肤上线；GPT 出图需求见 docs/design/GPT出图需求.md，出图后我照图换皮。
